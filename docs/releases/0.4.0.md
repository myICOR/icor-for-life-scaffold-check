# ICOR for Life - Scaffold Check 0.4.0

Knowledge quality. The check has always asked whether the scaffold's own
files are intact; it now also shows how healthy the knowledge base is, in
the report and on a new dashboard, with a trend per metric from this
plugin's own run history.

## What it does

- **Reads `.icor-for-life/scripts/quality.json`** (schema 1), written by the
  scaffold's `Scripts/check-quality.py --write`, which ships with ICOR for
  Life Scaffold 1.18.0. This plugin ships first, so every sentence that names
  the script also names the scaffold version that carries it. Thirteen
  metrics: notes
  without a link, enum violations, missing required fields, invented fields,
  orphans, dangling links, documents without a file, unprocessed scratchpads
  and their oldest, unprocessed captures and their oldest, unconsumed
  references, duplicate entities. **The plugin never measures.** It reads
  that one file and shows it.
- **The report gains a "Knowledge quality" section**, between the severity
  groups and "For your AI": the health in the heading, a metric table
  (label, value, severity as a word), the entity counts, and the findings
  grouped under their metric, twenty per metric with a "+n more" line.
  Frontmatter gains `quality_health`, `quality_generated`, `quality_stale`
  and one key per metric id. The "For your AI" prompt ends by sending the AI
  to the quality section and SOP-1014, propose first, apply after a yes.
- **A dashboard** (`icor-scaffold-dashboard`): "Open the Scaffold dashboard"
  in the command palette, plus a button in the result window. Both healths
  side by side, the counts row, and the metric table with an inline SVG
  sparkline per metric over the last thirty runs.
- **Run history** at `.icor-for-life/icor-for-life-scaffold-check/history.json`
  (schema 1), capped at ninety runs, created on first write.

## The four ways there is no data, and what each one says

None of them is an error, and none can stop a check.

| State | What you see |
| --- | --- |
| No file yet | One sentence: run `Scripts/check-quality.py --write` (ICOR for Life Scaffold 1.18.0 or later) in the ICOR for Life Terminal, or ask your AI to check your notes. |
| Another `schema` | Refused, naming the schema seen and the one expected. |
| Not valid JSON, or unreadable | Refused, one sentence, pointing at rewriting the file. |
| Older than seven days | Shown in full, with a stale marker and the age in days. |

## Reviewed against

Flint's review note on the 0.4.0 brief, every rule of which is in this build:

- `lastHealth` and `lastRun` stay in `data.json` for the status bar; run
  history and the last result do not, they are in the plugin's own subfolder
  of the machine layer.
- `quality.json` is read at run time and again when the dashboard view opens.
  No vault event fires for a hidden folder, so there is nothing to subscribe
  to and nothing is cached across a run.
- A missing file is an info line, never an error.
- `schema` is checked before any field is read.
- `adapter.list` answers with paths already prefixed by the folder, so
  `vaultFs.list` compares and returns full paths and never rejoins.
- `minAppVersion` stays 1.4.0 and `isDesktopOnly` stays false.

And GL-1008, the scaffold's machine-layer guideline: adapter API only through
`vaultFs` (extended with `write`, `mkdir`, `list` in this version, so nothing
reaches for the adapter inline any more), `exists` then `mkdir` of the
plugin's own subfolder before the first write, never a write outside it,
never a write into `scripts/`, another party's file read only through its
`schema` integer, unknown fields ignored, the folder never assumed to exist,
everything regenerable, per device.

## Tests

`npm test`, 81 passing (68 from 0.3.0, 13 new). The pure engine and its 36
scaffold gates were not touched: the quality file is read in `run()` and in
the dashboard view, never inside `runChecks`. The secrets source gate (no
`console` call, no `alert`, no token literal in the source) stays green.

Each new gate was watched going red against a mutated copy of `main.js`
before it was trusted, per GL-005 rule 4. Two mutations did not turn a test
red, both correctly: removing the `text == null` guard in `parseHistory` and
the empty-series guard in `sparklinePath` leaves the behaviour intact, since
a second guard downstream covers each. Removing both guards in the first
case, and inverting the geometry in the second, do turn them red.

## Not verified outside the test suite

This version was built and gated without a running Obsidian. What only a
live vault can settle:

- The dashboard view opens from the command palette and from the result
  window's button, and reveals an already-open leaf instead of a second one.
- `adapter.mkdir` of `.icor-for-life/` and then of
  `.icor-for-life/icor-for-life-scaffold-check/` on a vault that has neither,
  which is the state on a device that received the vault through Obsidian
  Sync. This is the one path where a wrong adapter assumption costs a write.
- `history.json` surviving a plugin reload and a second run appending rather
  than replacing, and the trend line appearing from the second run on.
- The inline SVG sparkline rendering inside a table cell in Obsidian's
  webview, and `currentColor` picking up the severity colour from the row.
- The `--ink-*` tokens against the INKLINE theme and the fallbacks against
  the default theme, in both light and dark mode.
- Phone width: the tiles wrapping, the metric table scrolling sideways inside
  its own box while the page does not, and the footer buttons wrapping.
- The report note rendering in reading view with the quality table and the
  per-metric finding groups, and the frontmatter keys showing up as
  properties (one key per metric id, thirteen of them).
- A real `quality.json` from the scaffold's script, rather than the fixture:
  the field shapes agreeing, and the metric ids matching one for one.

## Install

Copy `main.js`, `manifest.json` and `styles.css` from this release into
`.obsidian/plugins/icor-for-life-scaffold-check/` and enable the plugin under
Settings, Community plugins. The quality numbers appear once the scaffold's
`Scripts/check-quality.py --write` has run at least once; that script ships
with ICOR for Life Scaffold 1.18.0, so on an older scaffold the quality
section and the dashboard's metric table stay empty until you update.
