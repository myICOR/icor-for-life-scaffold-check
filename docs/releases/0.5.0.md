# ICOR for Life - Scaffold Check 0.5.0

The harness. ICOR for Life Scaffold 1.23.0 stopped shipping its AI-host
bindings typed by hand and started generating them from your own vault, so
two vaults on the same scaffold version now hold different bytes in those
files on purpose. This version reads that layer as generated rather than as
your editing, reports the per-device host links, shows what each AI host is
actually wired to, and checks that the Daily Scratchpad still keeps its
shape.

## What it does

- **The generated harness layer is read as generated.**
  `Scripts/scaffold-init.py apply` writes the skills, the Codex and Gemini
  agent shims, the hook configs and the host pointers from your vault's own
  frontmatter, and before this version the three-way file check called every
  one of them "you edited this file" on any vault that had hired a single
  agent. Every generated file opens with a header naming its source and
  carrying a content hash, and that header, never a path list, is what makes
  a file generated here, so the generator can change what it owns without
  this plugin learning about it. The hash is recomputed exactly the way
  `scaffold-init.py check` does it, including the JSON case where the header
  lives in a value because JSON cannot carry a comment. Intact means the file
  differs from the scaffold only because your source does. A mismatch means
  it was edited by hand, and the fix line names the generator and the source,
  never a hand edit and never a copy from the scaffold.
- **`.agents/skills/` is checked as what it is: per device.** Those links are
  written by the generator, never tracked and never shipped, so absent is not
  a finding. A link with no skill behind it IS a finding, because the host
  follows it, finds nothing and reports nothing. The test is whether the
  skill behind the link is readable rather than anything about symlinks,
  since the vault adapter has no `lstat` on any platform.
- **The Harness block.** `scaffold-init.py doctor --json` writes what it
  found about each AI host to `.icor-for-life/scripts/harness.json`, schema
  1, and this plugin reads that one file and shows it in the report and on
  the dashboard: per host what is detected, what is installed, whether the
  host trusts this folder, whether the guards have been watched go red, and
  what that host cannot do at all. A host with no hook system reads as not
  applicable rather than as untested, and a skipped red test is shown,
  because a skip is not a pass. The generator looks; this plugin only reads.
- **Whether Codex trusts this folder's hooks, in words.** The failure this
  uncovers is silent by design: `codex exec` never asks about hooks and runs
  none it has not been told to trust, without printing anything, so a member
  with untrusted hooks has every guard off and a terminal that looks exactly
  like one where they are on. A host that is not trusted lifts the Harness
  health, so the heading can never read ok above that line. An unreadable
  config reads unknown and never no.
- **The Daily Scratchpad keeps its shape.** A ninth check reads every file in
  `00 Daily Scratchpad/` and points at the ones that are not where `GL-1004`
  says they go: a capture loose at the room root, a capture nested only by
  year, a note named for its subject rather than its date, and a saved view
  buried inside a dated folder. One finding per file, because the fix is per
  file. The shapes that pass are the ones the real tools produce, and the two
  legacy timestamp shapes stay legal so an older vault is not called broken
  for its history.
- **Nothing under `.icor-for-life/scripts/` is ever reported as drift.** The
  per-session receipts, `session.json`, `harness.json` and this plugin's own
  run history are state, not sources, which is GL-1008's membership test.
  `.icor-for-life/VERSION`, which does ship, is still read.

## Reviewed against

Flint's review-before-ship read of this build was CONDITIONAL with three
conditions in `main.js`, all three landed before this tag:

- **A dangling link does not appear in a desktop listing, it ends the
  listing.** The adapter stats every entry, so a link with no target throws
  and the whole listing rejects, which turned the one input this check exists
  to catch into an Info line saying nothing could be looked at. A rejected
  listing is now the finding, and every canonical skill name is still probed
  one by one through `exists`, which never throws.
- **Line endings are normalised before any hash.** The generator writes
  `os.linesep` on Windows and reads back under universal newlines, so without
  this every generated file on Windows would read as hand-edited forever and
  the fix it printed would rewrite the same bytes.
- **A phone is answered before anything is read.** Codex, Gemini CLI and
  Cursor do not run there, so the report says which rather than blaming the
  adapter.

`minAppVersion` stays 1.4.0 and `isDesktopOnly` stays false: nothing in this
version moves the floor. No Node import, no DOM injection, no new network
call; the one `requestUrl` to the manifest URL is unchanged and disclosed in
the README.

## Tests

`npm test`, 118 passing (81 from 0.4.0, 37 new). The hash fixtures are real
1.23.0 generator output rather than this plugin's idea of it, one copied byte
for byte and one hashed by the generator's own arithmetic, because a test
that builds its input with the code under test proves only that the code
agrees with itself. Twenty gates were each watched go red by removing the
code behind them before any of it was trusted, and one of them was rewritten
because the first version stayed green with the code removed.

## Known

Seven `addEventListener` calls remain where the plugin guideline prefers
`registerDomEvent`. The one that was a clean win, the status bar item
registered once in `onload`, is changed. The other six are not, on purpose:
three sit in a `Modal` and a `PluginSettingTab`, neither of which is a
`Component`, so the only `registerDomEvent` available belongs to the plugin
and would hold every handler until unload, which for a modal opened
repeatedly is a leak rather than a fix. The other three are in a view that
re-renders on a button press and `empty()`s its own container each time. In
every one of the six the listener dies with the node.

## Install

Copy `main.js`, `manifest.json` and `styles.css` from this release into
`.obsidian/plugins/icor-for-life-scaffold-check/` and enable the plugin under
Settings, Community plugins. The harness block and the generated-file
handling need ICOR for Life Scaffold 1.23.0 or later; on an older scaffold
there is no harness file to read and no generated header to find, and both
say so in one sentence instead of erroring.
